# 参考样例库（阶段 2 直接抄给用户挑）

用户说不清想要什么，但**很会挑**。这一页是现成的选择题选项组：把菜单原样贴进问询里，
首项永远是推荐项（带理由），末尾永远留一个「都可以 / 你决定」。

用法：每组的首项复制到 `Q#` 的第一行，其余选项照抄或按场景改写。
**不要一次给用户超过 4 个选项。**
例外是 **K 组**：那是阶段 2.5 的扩充清单，一次给 6~8 项、每项自带默认档，用户不勾就照默认走。

---

## A. 产物形态菜单（Q1 通用）

```text
- [推荐] <最小可跑形态>，理由：能立刻看到结果，改起来最便宜
- 带参数/子命令的命令行工具
- 带界面的应用（工期约 ×2，需要额外做交互与样式）
- 只输出一份文档或提示词，不写代码
```

## B. 完成度档位菜单（Q3 通用 —— 直接决定验收强度）

| 档位 | 一句话 | 配套要求（写进提示词） |
| --- | --- | --- |
| **一次性用完就扔**（推荐默认） | 跑通一次就行 | 1 个冒烟脚本；不写单测 |
| **能长期反复跑** | 每周都要用 | 幂等 + 错误日志 + 1 组核心用例 |
| **要给别人用** | 陌生人拿到能跑 | README + `--help` + 失败提示 + 版本锁定 |
| **要上生产** | 出事有代价 | 单测覆盖核心分支 + 回滚方案 + 监控/告警口径 |

## C. 技术栈菜单（Q5）

```text
- [推荐] 沿用你当前项目已有的栈（<从工作区实测出来的语言与版本>），理由：不引入第二套工具链
- Python 3.11 + 仅标准库，理由：零依赖，换机器就能跑
- Node 20 + 仅内置模块
- 允许引入第三方库（请指定包名；我会写进依赖清单并锁定版本）
```

## D. 运行与交付环境菜单（Q5 补充）

```text
- [推荐] 本机命令行，Windows 可用，双击 .cmd 也能跑
- 本机 + 定时任务（每天/每周自动跑）
- 内网服务器（需要写部署步骤与开机自启）
- 公网（需要写域名、HTTPS、并发与安全约束）
```

## E. 数据边界菜单（Q6 —— 涉及隐私时必问）

```text
- [推荐] 全部在本机处理，不联网、不上传
- 允许调用外部 API（请说明密钥从哪来、失败怎么办）
- 允许读取 <某目录/某系统>，但禁止写入
- 允许写入，但必须先备份到 <某目录>
```

## F. 验收强度菜单（Q7 —— 用户不想想数值时用这组）

```text
- [推荐] 定 3 条硬验收（能跑通 / 结果对 / 不误删）
- 加性能阈值（给出数字：处理 N 条 ≤ M 秒）
- 加兼容矩阵（OS / 版本 / 浏览器）
- 只要"我看一眼觉得行"（判定改为：人工，用户本人看）
```

## G. 风格与内容参照（Q4 —— 用户要"好看"时用这组）

给参照物比给形容词有用：

```text
- [推荐] 参照 <现成截图/竞品链接>，理由：已有的东西不用重新描述
- 从下面三种基调里挑一个：<A 克制的工具感> / <B 高对比的营销感> / <C 极简黑白>
- 我来提供配色与字号（我会等你给色值，不自己编）
- 都可以，你按内容推导并给一套设计令牌（色值/字号/间距）写进提示词
```

配色/字号/间距一律落成**可复制的令牌**（`#0B0B12`、`16/20/28/40`、`4/8/12/24`），不许停在「简洁大气」。

## H. 常见需求形态 → 推荐选项组（组合拳）

| 用户的一句话 | 问题顺序 | 首项推荐 |
| --- | --- | --- |
| 「帮我写个脚本，把下载文件夹整理一下」 | 产物形态 → 分类规则 → 冲突处理 → 干跑开关 → 环境 | A1 单文件脚本 · B1 一次跑通 · 分类按扩展名 · 同名追加序号 · `--dry-run` 默认 |
| 「帮我做个报名网站」 | 规模 → 部署 → 登录 → 数据落库 → 截止时间 | 单页 Web + 本地 SQLite · 内网/公网先定 · 不做账号（用姓名+手机号） · 并发 50 |
| 「把这份需求写成给 AI 的提示词」 | 目标 AI → 产物形态 → 完成度 → 验收强度 | 目标 AI = Claude Code · 产物 = 单人可跑的形态 · B2 · F1 |
| 「我这个项目想重构一下」 | 痛点定位 → 允许改动范围 → 回归基线 → 不许动的部分 | 只重构 <某模块> · 不改对外接口 · 用现有测试当基线 · 禁止升级大版本依赖 |
| 「帮我做个能自动整理会议纪要的工具」 | 输入形态 → 输出结构 → 是否联网 → 隐私边界 | 本地文本/录音转写稿 · 输出固定小标题结构 · 不联网 · E1 全本机 |
| 「给我这个仓库做个 Agent Skill」 | 触发词 → 目标 AI → 落盘目录 → 验收样例 | 触发词 3~5 个 · DSH / Claude Code · `~/.claude/skills/<name>/` · 用 1 个真实任务试跑 |

## I. 反例菜单（用户挑不出想要的，就让他挑讨厌的）

## K. 内容扩充菜单（阶段 2.5 —— 问「这份提示词写多厚」）

前 A~J 组都是**要用户回答问题**；K 组是**一次给出的清单**，每项自带默认档，用户不勾就照默认走。
界线：菜单里**不许出现只有用户能回答的问题**（那些属于阶段 2 问询），这里只放「要不要包含 X」。

按需求形态取 **6~8 项**（上限 12 项），首行永远放那句总说明：

```text
这份提示词要不要包含下面这些？不勾的就按默认走；嫌麻烦直接说「全按默认」。
- [默认 要] 错误处理与失败路径 —— 代价：+2 条需求、+1 条验收
- [默认 要] 边界与空数据（0 条 / 1 条 / 超大 / 没权限） —— 代价：+1~2 条需求
- [默认 要] 幂等（重复跑不重复干活） —— 代价：+1 条需求、+1 条验收
- [默认 不要] 性能预算（要写数字与测量方法） —— 代价：+1 条阈值验收
- [默认 不要] 部署与回滚步骤 —— 代价：+1 段步骤、要问清密钥来源
- [默认 不要] 单元测试与覆盖率门槛 —— 代价：工期 +30%~50%
```

### K1. 通用项（按形态挑 6~8 条）

| 项目 | 默认 | 代价 / 说明 |
| --- | --- | --- |
| 错误处理与失败路径 | 要 | +2 条需求、+1 条验收；不写就会出现「跑一半崩了不知道怎么办」 |
| 边界与空数据（0 条 / 1 条 / 超大 / 权限不足） | 要 | +1~2 条需求；这类输入是返工第一来源 |
| 幂等 / 重跑安全 | 要（会重复跑的才要） | +1 条需求、+1 条验收 |
| 与现有代码和约定兼容（不改对外接口、不加新依赖） | 要 | 免费：直接写进技术约束段 |
| 性能预算（数字 + 测量方法） | 不要 | +1 条阈值验收；没有真实规模数据时先别写，进假设段 |
| 部署与回滚步骤 | 不要 | +1 段步骤；要额外问清部署目标与密钥来源 |
| 单元测试与覆盖率门槛 | 不要 | 工期 +30%~50%，且要有真能跑测试的环境 |
| 日志与可观测性口径 | 不要 | +1 条需求；一次性脚本通常不需要 |
| 数据迁移 / 兼容旧数据 | 不要 | 要额外一轮数据口径确认 |
| 多语言 / 国际化 | 不要 | +1 条需求 + 一份文案清单 |
| 安全与隐私边界（密钥、脱敏、不上传） | 涉及真实用户数据时**自动变要** | +1 条需求 + 非目标；不写容易踩合规 |
| 后续迭代路线（下一版做什么） | 不要 | 默认不进提示词：那是下一次要谈的事 |

### K2. 按需求形态的默认组合

| 形态 | 默认勾上 | 默认不勾 |
| --- | --- | --- |
| 一次性脚本 | 错误处理、边界与空数据、幂等 | 性能预算、测试门槛、部署回滚、可观测性 |
| Web / 应用（内网或公网） | 错误处理、边界与空数据、性能预算（并发量级）、部署与回滚 | 覆盖率门槛、国际化 |
| 数据处理 / 报表 | 错误处理、边界与空数据、幂等、日志口径 | 部署回滚、国际化 |
| 重构 / 修 bug | 与现有代码兼容、错误处理、回归验证方式 | 性能预算、部署回滚 |
| 给别人用 / 团队工具 | 错误处理、边界与空数据、部署与回滚、可观测性、测试门槛 | 国际化（除非真有） |
| Agent Skill / 提示词 | 边界与空数据（触发边界）、错误处理（误触发怎么办） | 性能预算、部署回滚 |

勾「要」的必须出现在 `prompt.md` 对应段落；勾「不要」的按 `references/需求问询.md` 第 7.2 节落进非目标段或假设段，不许凭空消失。
