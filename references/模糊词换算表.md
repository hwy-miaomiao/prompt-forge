# 模糊词换算表（阶段 3 撞到形容词时）

规矩：**形容词进不了需求段和验收段**。撞到一个，就在下表换算成数字、路径、或判定方式；
换算不出来，说明这件事还没问清楚 —— 回去要参照物，或者写进「假设与开放问题」段标 `未确认`。

> 词表以 `scripts/check_prompt.py` 里的 `VAGUE_WORDS` 为准（机器闸门用同一份词表）；
> 本表是给人看和给 AI 换算用的版本，两边改动要同步。

## 1. 换算表

| 模糊说法 | 必须换成 | 换算示例 |
| --- | --- | --- |
| 快 / 快点 / 尽快 | 延迟或时长上限 + 测量口径 | 「1000 个文件 ≤ 30 秒（本机 SSD，取 3 次中位数）」 |
| 高性能 | 明确指标：吞吐 / P95 / 内存峰值 | 「P95 ≤ 200 ms；常驻内存 ≤ 150 MB」 |
| 秒开 | 首屏可交互时间 | 「首屏 TTI ≤ 1.0 s（本机 Chrome，冷启动）」 |
| 好看 / 美观 / 大气 / 高级感 / 有质感 | 参照物 + 设计令牌 | 「参照 `ref/home.png` 的版式；主色 `#0B0B12`，字号 16/20/28/40，间距 4/8/12/24」 |
| 简洁 / 清爽 / 简单点 | 可数的量 | 「单文件 ≤ 200 行；依赖 0 个；README ≤ 60 行」 |
| 流畅 / 不卡 | 帧率或响应时间 | 「滚动 ≥ 55 fps；点击到反馈 ≤ 100 ms」 |
| 稳定 / 可靠 | 失败率 + 重复次数 | 「连续跑 20 次 0 崩溃；单文件失败不影响其余文件」 |
| 易用 / 好用 / 友好 | 完成任务所需步数与前置知识 | 「新用户不看文档，3 步内完成首次整理」 |
| 尽量 / 尽可能 / 最好能 | 删掉，改成优先级与取舍规则 | 「优先保数据完整；冲突时宁可不动并记日志」 |
| 在可行范围内 / 如需要 / 必要时 / 视情况 | 删掉，改成默认行为 + 触发条件（INCOSE 把这类词叫 **escape clause / 逃逸条款**：它让需求在任何情况下都能被解释成"没做到也不算违约"） | 「默认不覆盖已有文件；仅当带 `--force` 时覆盖」 |
| 合理 / 适当 / 差不多 | 阈值或明确取值 | 「超过 30 天未访问的文件才归档」 |
| 优化一下 / 改进一下 / 处理一下 | 具体动作 + 可观察结果 | 「把 <函数> 里的 N+1 查询合并为 1 次；`EXPLAIN` 不再出现 nested loop」 |
| 一些 / 若干 / 大量 | 数量级 | 「≥50 条 / ≤5 GB / 约 1 万行」 |
| 等等 / 类似的东西 | 穷举，或写明扩展规则 | 「扩展名表：jpg png gif；新增类型改 `EXT_MAP` 一处即可」 |
| 完善 / 丰富 / 强大 | 具体条目清单 | 「支持 4 个子命令：init / run / status / clean」 |
| 兼容 / 支持多平台 | 版本矩阵 | 「Windows 11 + Python 3.11；macOS 与 Linux 不保证」 |
| 安全 | 具体禁则 | 「密钥只从环境变量读，禁止落盘；日志禁止打印 token」 |
| 用户体验好 | 具体交互断言 | 「失败时打印『原因 + 下一步怎么做』两行，不打印 traceback」 |
| 相关的 / 类似的 | 明确的集合 | 「只处理 `图片/` 与 `文档/` 两个目录」 |
| 大概 / 基本 | 精确值或范围 | 「约 1284 个文件（实测），允许 ±10%」 |
| 看着办 / 你懂的 | 禁止出现，必须变成一条假设 | 「未确认：默认按扩展名分类」 |

## 2. 换算不出来的三种情况

1. **用户自己也说不清**（审美类最多）→ 要参照物：截图、链接、竞品名、老项目路径。
2. **依赖外部事实**（平台限制、第三方接口速率）→ 自己查（阶段 1 预调研），把 URL 写进背景段。
3. **需要用户拍板**（工期、预算、能不能动生产数据）→ 变成问询题，不要自己定。

## 3. 反向检查：验收段里的每个数字都要有测量方法

写「≤ 30 秒」不够，要写**怎么量**：用什么命令、跑几次、取哪次、什么机器。
否则执行者会用最有利的方式量，验收就失去意义。

| 不合格 | 合格 |
| --- | --- |
| 处理速度要快 | `time python tidy.py` 在 1284 个文件（约 5 GB）上 ≤ 30 秒 |
| 界面要好看 | 与 `ref/home.png` 并排截图对比，色值差 ≤ 3 个十六进制位，版式一致 |
| 要稳定 | 连续 `for i in 1..20; do python tidy.py --dry-run; done` 全部退出码为 0 |
| 错误提示要友好 | 人为造一个不可读文件，运行后 stderr 出现一行中文原因 + 「跳过并记录到 errors.log」 |
