# 校验清单（阶段 4）

分两道：**机器闸门**（`scripts/check_prompt.py`，不通过就不许交付）与**人工复核**（必须逐项打勾）。
机器只管结构，人工只管"这个提示词换个人来读会不会做错"。

## 一、机器闸门

```bash
python scripts/check_prompt.py <输出目录>/prompt.md
```

退出码：有 ERROR 时非零。通过条件：**0 ERROR**；WARN 要逐条说明为什么不影响执行。

### ERROR（必须修，修不了就说明清楚）

| 码 | 检查什么 | 怎么修 |
| --- | --- | --- |
| E0 | 全文没有任何 Markdown 标题 | 用 `templates/提示词骨架.md` 的 12 段标题 |
| E1 | 缺少必需段落（12 段契约） | 补上缺的那一段，不要合并段落 |
| E2 | 编号需求 `R#` 少于 3 条 | 拆需求；一条需求一件事 |
| E3 | 编号验收 `A#` 少于 3 条 | 每条需求至少配一条验收 |
| E4 | 某条 `A#` 没引用任何 `R#` | 写成 `A2（对应 R2）` |
| E5 | 某条 `A#` 没有 `判定：` | 补 `判定：命令…` / `判定：阈值…` / `判定：人工…` |
| E6 | 某条 `R#` 没有任何 `A#` 覆盖 | 给它配验收，或把它移到第 10 段当假设 |
| E7 | 非目标段为空或只写「无」 | 至少写 1 条不做什么 |
| E8 | 交付物段没有带扩展名的路径 | 写精确路径，如 `out/report.csv` |
| E9 | 需求段/验收段出现模糊词 | 按 `references/模糊词换算表.md` 换算成数字或判定方式 |
| E10 | 残留占位符（TODO / TBD / 待补充 / 待填 / 待定 / XXX / ???） | 填实或删掉 |

### WARN（可接受，但要解释）

| 码 | 检查什么 | 处理建议 |
| --- | --- | --- |
| W1 | 全文 < 600 字符 | 检查是不是把长提示词写成了短提示词 |
| W2 | 某条 `R#` 没有数字/路径/具体对象 | 多半不可验证，补量化 |
| W3 | 假设段为空 | 一条假设都没有，通常说明替用户拍板了 |
| W4 | 验收条目 > 25 条 | 合并同类项，或分层（必须 / 可选） |
| W5 | 需求条目 ≥ 15 条 | 分层，或拆成两个提示词 |
| W6 | 非目标只写了 1 条 | 补到 2 条以上 |
| W9 | 非需求段出现模糊词 | 看上下文：背景段的引用可以保留，约束段要换算 |

### 自测（改了脚本或示例后必须跑）

```bash
python scripts/check_prompt.py --selftest
```

期望：两个正例 0 ERROR，反例 ≥5 ERROR。**正例必须过闸门、反例必须被拦下**，否则脚本失去了判据。

## 二、人工复核（逐项打勾）

### A. 陌生人测试（最重要，一次就够）

- [ ] **把本次对话全部删掉**，只留 `prompt.md`，另一个 AI 能不能读懂？有没有「上面说的」「之前那个」？
- [ ] 每一处**路径**都是可解析的（绝对路径或相对仓库根），没有「合适的位置」「相应目录」。
- [ ] 每一处**版本号**都是具体数字，没有「最新版」「合适的版本」。
- [ ] 每一处**事实**都带来源标记（`[用户原话]` / `[仓库实测]` / `[外部资料 URL]` / `[AI 推断]`）。
- [ ] 每个 `[AI 推断]` 都在第 10 段出现过。

### B. 需求与验收

- [ ] 每条需求都能想象出「做完了长什么样」；想象不出来的重写。
- [ ] 每条验收都引用了需求编号，没有凭空出现的验收。
- [ ] 每条验收的 `判定：` 都能**当场执行或当场看**（不是「测试一下」）。
- [ ] 带数字的验收都写了**测量方法**（命令、次数、机器）。
- [ ] 验收里没有「通过 / OK / 正常」这类没有口径的词。

### C. 边界与风险

- [ ] 非目标段真的拦得住「顺手扩展」吗？用户看完会不会觉得「我明明说过不要这个」？
- [ ] 有没有**替用户拍板**的地方？每处都进了第 10 段吗？
- [ ] 第 11 段的触发条件是可识别的（不是「遇到问题就问」）？
- [ ] 涉及删除/覆盖/对外发送/花钱的动作，都在第 11 段设了卡点吗？
- [ ] 汇报格式的「三件套」在最后一段写明了吗？

### D. 交付形态

- [ ] `prompt.md` 落在 `<输出目录>/`，没有写进工具目录。
- [ ] `需求确认.md` 记的是**用户原话**与用户的选择，不是你的推断。
- [ ] 回复里贴了长提示词**全文**（不是只说「已写入文件」）。
- [ ] 回复里点了「最可能返工的三处」。

## 三、交付话术模板

```text
长提示词已生成：<输出目录>/prompt.md（已过闸门：0 ERROR，N WARN）

<提示词全文>

最可能返工的三处：
1. <推断项 1>（默认取 …，改一句话要连带改第 X 段与第 Y 段）
2. <推断项 2>
3. <推断项 3>

要改的话直接说「第 X 段改成 …」，我只重做受影响的部分并重跑闸门。
```
