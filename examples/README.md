# 示例：一句话是怎么变成能开工的长提示词的

四个文件：

| 文件 | 用途 |
| --- | --- |
| `例1-下载文件夹整理.prompt.md` | 正例：脚本类需求，**必须 0 ERROR**（脚本自测用） |
| `例2-班级报名网站.prompt.md` | 正例：Web 类需求，**必须 0 ERROR** |
| `例3-logsift-json-export.prompt.md` | 正例：改造已有仓库类需求（给既有 Python CLI 加 `--json` 导出），**必须 0 ERROR** |
| `反例-模糊需求.prompt.md` | 反例：典型的"一句话丢给 AI"，**必须被拦下 ≥5 个 ERROR** |

自测（改了脚本或示例后必跑）：

```bash
python scripts/check_prompt.py --selftest
# PASS  例1-下载文件夹整理.prompt.md: 0 ERROR（期望 0 ERROR）
# PASS  例2-班级报名网站.prompt.md: 0 ERROR（期望 0 ERROR）
# PASS  例3-logsift-json-export.prompt.md: 0 ERROR（期望 0 ERROR）
# PASS  反例-模糊需求.prompt.md: 16 ERROR（期望 >=5 ERROR）
# PASS  templates/提示词骨架.md: 0 ERROR, 0 WARN（期望 0 ERROR 0 WARN）
```

自测扫的是 `examples/*.prompt.md` 全部四个文件：名字里带「反例」的按 **≥5 ERROR** 判，
其余按 **0 ERROR** 判；另外把仓库自带的 `templates/提示词骨架.md` 也单列成一个用例
（要求 **0 ERROR 0 WARN** —— 给人抄的模板自己必须先干净）；
判据硬编码在 `scripts/check_prompt.py` 的 `selftest()` 里。

## 还有一组：`examples/技能定义/`（闸门②的夹具）

上面四个文件验的是**长提示词**；[`技能定义/`](技能定义/README.md) 验的是**这个技能自己的定义**
能不能被宿主自动识别 —— 名字合不合规、描述里有没有"何时该用 / 何时不该用"、
薄包装有没有把同目录的规范一起带上。11 个目录（2 正 9 反）+ 每个的预期 ERROR/WARN 码见
[`技能定义/README.md`](技能定义/README.md)。其中 `evidence-images/` 与 `evidence-fake/`
是第 9 轮新增的「迭代证据」一正一反：声明 `evidence: 2 images` 后，正文迭代记录里必须引用
真实存在、魔数正确的 PNG/JPEG/WebP 相对路径（细节见 `references/校验清单.md` 闸门② 的迭代证据约定）。

```bash
python scripts/check_skill.py --selftest
# PASS  SKILL.md: 0 ERROR（期望 0 ERROR）
# PASS  [示例] good-minimal: ERROR [] WARN []（期望 ERROR [] WARN []）
# PASS  [示例] evidence-images: ERROR [] WARN []（期望 ERROR [] WARN []）
# PASS  [示例] evidence-fake: ERROR ['E8', 'E9'] WARN []（期望 ERROR ['E8', 'E9'] WARN []）
# ... 其余 8 个反例逐个 PASS，最后 `自测结果：全部通过`（共 76 个用例）
```

## 还有一组：`examples/需求确认/`（闸门④的夹具）

上面四份验的是 `prompt.md`，这一组验的是 `需求确认.md`：分诊三态、五步证据链、问询模式、
每道题的方法来源与「落到 prompt.md 哪一段」的追溯。

| 文件 | 用途 |
| --- | --- |
| `需求确认/例1-下载文件夹整理.需求确认.md` | 正例：完整走完 go / 菜单式 / 五步证据链 / Q1-Q4 带方法来源，**必须 0 ERROR 0 WARN**（闸门④ 实跑用） |
| `需求确认/反例-需求确认缺证据链.需求确认.md` | 反例：缺证据链、缺方法来源、答案空白，**必须被拦下 ≥5 个 ERROR** |

```bash
python scripts/check_confirm.py "examples/需求确认/例1-下载文件夹整理.需求确认.md"
# 结果：0 ERROR, 0 WARN —— 通过
python scripts/check_confirm.py --selftest   # 65 个用例 + 2 个 --no-ignore 用例 + 1 个模板负例（68 PASS）
```

## 这些文件还要过闸门③（跨段一致性）

闸门① 只管"每段自己写得对不对"，`python scripts/check_contract.py <文件>` 另外查段与段之间对不对得上：
三条正例与 `templates/提示词骨架.md` 都是 **0 ERROR 0 WARN**（第 9 段的步骤写了 `（对应 R#）`、
第 10 段的 `未确认` 在第 11 段有对应的停下条件）。反例那边闸门③ 会打印一句范围说明
（这份文件没有可认的第 9 段，`C2` 无从检查；段落缺失归闸门① 报 `E1`）并照常通过 —— 反例本来就不是靠闸门③ 拦的。
CI 会拿三个正例 + 骨架 + 闸门④ 正例 + 两个 evidence 技能示例实跑一遍，并检查两份反例与两个技能反例都被拦下
（见仓库根的 `.github/workflows/ci.yml`）；单入口 `python scripts/check.py examples` 一条命令能同时看到这些结果。

## 例 1：从「帮我写个脚本，把下载文件夹整理一下」到 3923 字符的提示词

**用户原话**：「帮我写个脚本，把下载文件夹整理一下。」

### 问了 7 题（上限 9 题，能压到 5 题更好；一轮问完，每题首项是带理由的推荐项）

| # | 题目 | 用户的选择 |
| --- | --- | --- |
| Q1 | 交付物形态 | 单文件 Python 脚本 + 双击入口（推荐项） |
| Q2 | 分类规则 | 按扩展名分四类（推荐项） |
| Q3 | 同名冲突怎么办 | 追加 `-1`、`-2`（推荐项） |
| Q4 | 完成度档位 | 能长期反复跑（用户补了「每周都要用」） |
| Q5 | 移动失败怎么处理 | 跳过并记日志，不中断（推荐项） |
| Q6 | 有没有不能碰的东西 | 不能删任何文件；`.part` 之类的半成品不要动 |
| Q7 | 性能期望 | 1000 多个文件，一分钟内（用户给了量级） |

其中 Q6、Q7 直接变成了非目标段与 `R3`/`R6`；Q4 的「每周都要用」把完成度从"一次性"抬到"幂等 + 日志"。

### 一句话 → 提示词的差别在哪

| 用户的一句话 | 提示词里 |
| --- | --- |
| 整理一下 | `R1` 按扩展名分到四个子目录，扩展名表可改 |
| （没说冲突） | `R2` 同名追加 `-1`，最多 `-99` |
| （没说禁用） | `R3` 目录/隐藏文件/`.part` 一律不动 |
| （没说失败） | `R4` 失败跳过并记日志，退出码仍为 0 |
| （没说干跑） | `R5` `--dry-run` 只打印不移动 |
| （没说速度） | `R6` 1284 个文件 ≤ 60 秒，附计时方法 |
| 千万别删东西 | 非目标 5 条 + `A4` 文件数差值 = 0 + 第 11 段卡点 |

**产出的不是"更啰嗦的句子"，而是 7 条可验收的需求 + 6 条带判定的验收。**

## 例 2：从「我们班要做个报名网站」到带并发指标的提示词

**用户原话**：「我们班 42 个人，周末活动报名用，手机点开就能填，别让人填一堆东西。」

差异最大的是两处：

1. **性能被钉成数字**：从"人不多应该没事"变成 `R5`「42 并发，P95 ≤ 500 ms」，
   并在 `A5` 给出测量命令（`ab -n 100 -c 42`）。
2. **隐私边界显性化**：非目标里写了"不接第三方服务、名单页只读、手机号打码"，
   第 11 段设了"要收集更多个人信息必须停下来问人"的卡点 —— 这是用户没说、但必须写清楚的部分。

跑闸门时 `例2` 会命中 1 条 WARN（`W2 需求 R2`）：R2 的量化写在配对的 `A2` 里（命令 + 期望行数），
需求行本身没有数字（`W2` 看的是整条 `R#` 条目，含它的续行，但不拿配对的 `A#` 来判）。
这是设计内的提示 —— 正例的判据是 **0 ERROR**
（WARN 逐条说明即可，见 `references/校验清单.md`），`--selftest` 也只看 ERROR 数。

## 例 3：改造已有仓库 —— 给 logsift CLI 加 `--json` 导出

**用户原话**：「logsift 那个日志分析脚本，想让它能导出 JSON 给别的脚本用，再就是出错的时候别只报一行。」

例 1 / 例 2 都是「从零开始」；这一例演示**产物落在现有仓库**时怎么写：
阶段 0 先确认仓库位置与现有约定，第 9 段按现有目录写步骤（先读 `pyproject.toml` 与既有测试、先补失败测试再改代码、
抽 `render.py` 渲染层、`cli.py` 只做参数接线），并给出「改坏了怎么退回去」的可中断点。
交付物全部带精确路径与行数上限，退出码写成常量，JSON 字段写成 schema —— 提示词是给陌生人看的，
执行的人看不到这个仓库之外的上下文。

跑闸门：`python scripts/check_prompt.py examples/例3-logsift-json-export.prompt.md` 与
`python scripts/check_contract.py examples/例3-logsift-json-export.prompt.md` 都是 **0 ERROR 0 WARN**，
并且和例 1 / 例 2 / 骨架一起进 CI 的资产闸门。

## 反例：一句话丢给 AI 会发生什么

`反例-模糊需求.prompt.md` 会被闸门拦下 16 个 ERROR（另有 5 条 WARN：`W1` 全文过短、
`W2` 需求 R1/R2 没有量化、`W9` 模糊词 ×2），分五类：

| 类型 | 具体 |
| --- | --- |
| 结构缺失（E1×9） | 没有角色与目标、背景、非目标、技术约束、验证方式、执行步骤、假设、问人卡点、汇报格式 |
| 需求不可验收（E2/E3/E4/E5） | 只有 2 条需求、1 条验收，且验收既没引用需求也没有判定方式 |
| 需求没被验收覆盖（E6×2） | R1、R2 都没有对应的 `A#`（同一段里 A1 也没引用它们） |
| 交付物没路径（E8） | 写的是「放在合适的位置就行」 |
| 模糊词（W9×2） | 好看、看着办 —— 出现在一级标题段「帮我做个网站」（第 3、4 行）；「方便」被「每行只报第一个词」的规则吞掉、「性能好」不在模糊词表里，两者都没出现在输出里 |

同一份需求，走完本仓库的流程后就是 `例2`。**两者不是"字数差别"，是"能不能验收的差别"。**
