# 任务：给班级做一个周末活动报名网页（Python + Flask + SQLite，内网可用）

## 1. 角色与目标

你是一名后端工程师。目标：做一个单页报名网站，同学用手机连内网就能填表报名，班长打开名单页能看实时名单。

做完算成功的定义：班长执行 `python app.py` 后，班里 42 位同学用手机在同一 WiFi 下打开地址，
30 秒内各自完成一次报名，名单页出现 42 条互不重复的记录。

## 2. 背景与已知事实

- [用户原话] 「我们班 42 个人，周末活动报名用，手机点开就能填。」
- [用户原话] 「不想注册账号，填个名字手机号就行，别让人填一堆东西。」
- [用户原话] 「报名截止到 10 月 18 号晚上 8 点。」
- [外部资料 https://flask.palletsprojects.com/en/3.0.x/quickstart/] Flask 3 默认开发服务器单线程，压测需要 `threaded=True`。
- [AI 推断] 班长最后要把名单导出来发给老师（未确认，见第 10 段）。

## 3. 交付物

| 路径 | 是什么 | 格式 / 规模 |
| --- | --- | --- |
| `E:\class-signup\app.py` | 服务与路由 | 单文件，≤200 行 |
| `E:\class-signup\templates\index.html` | 手机端报名页 | 单文件，内联 CSS |
| `E:\class-signup\templates\list.html` | 名单页（只读） | 表格，≤40 行 |
| `E:\class-signup\export.py` | 导出脚本 | 生成 `out.csv` |
| `E:\class-signup\signup.db` | SQLite 数据库 | 单文件，一张表 |
| `E:\class-signup\README.md` | 部署与使用说明 | ≤60 行 |

## 4. 需求（R#）

- **R1** 报名页三个字段：姓名（2~10 个字）、手机号（11 位数字）、随行人数（0/1/2）；提交成功后页面显示「报名成功，序号 N」。
- **R2** 同一手机号重复提交按修改处理，不新增记录（总数不增加）。
- **R3** 截止时间 `2026-10-18 20:00`（Asia/Shanghai）之后提交一律拒绝，返回提示页且不写库。
- **R4** 名单页 `/list` 按提交时间升序显示：序号、姓名、手机号（中间四位打星号）、随行人数、提交时间。
- **R5** 42 人同时提交时，页面响应 P95 ≤ 500 ms（内网同一台笔记本，`threaded=True`）。
- **R6** 数据落在单个 SQLite 文件；`python export.py` 生成 UTF-8 的 `out.csv`，首行表头为 `序号,姓名,手机号,随行人数,提交时间`。
- **R7** 部署方式：`python app.py` 启动并监听 `0.0.0.0:8000`，启动时打印本机内网地址供同学输入。

## 5. 非目标

- 不做账号体系、登录、验证码与找回密码。
- 不做在线支付、不做活动相册、不做评论。
- 不接入任何第三方服务：不引 CDN、不加统计脚本、不发短信。
- 不做后台管理界面，名单页只读，不允许在网页上删改记录。
- 不支持公网部署与 HTTPS（只在班级内网使用）。

## 6. 技术约束

- Python 3.12 + Flask 3.0（唯一第三方依赖），模板用 Jinja2，依赖写进 `requirements.txt` 并锁版本。
- SQLite 3 单文件，直接用 `sqlite3` 标准库，不引入 ORM、不做迁移框架。
- 前端单文件内联 CSS，不引入任何 JS 框架；按 375 px 宽度优先设计，字号 ≥16 px。
- 时间一律按 `Asia/Shanghai` 处理，入库用 `YYYY-MM-DD HH:MM:SS` 文本。
- 禁止把完整手机号写进日志或异常信息。

## 7. 验收标准（A#）

- **A1（对应 R1）**：手机浏览器打开报名页，填三项提交，页面出现「报名成功，序号 1」，名单页同步出现该记录。判定：人工 用户 用手机在同一 WiFi 下实测一次，看到成功提示与名单记录即为通过。
- **A2（对应 R2）**：同一手机号提交两次后，库中仍只有 1 条记录。判定：命令 `python export.py` 后统计 `out.csv` 行数 —— 期望 2 行（表头 + 1 条数据）。
- **A3（对应 R3）**：把截止时间临时改为过去时间后提交，记录数不变。判定：阈值 提交前后 `select count(*) from signup` 差值 = 0（测量方法：用 `python -c "import sqlite3;print(sqlite3.connect('signup.db').execute('select count(*) from signup').fetchone()[0])"` 各测一次）。
- **A4（对应 R4）**：名单页手机号显示为 `138****8888`。判定：人工 用户 打开 `/list`，确认中间四位为四个星号且序号按时间升序排列。
- **A5（对应 R5）**：并发压测。判定：阈值 P95 ≤ 500 ms（测量方法：`ab -n 100 -c 42 http://127.0.0.1:8000/` 输出中 95% 那一行的耗时）。
- **A6（对应 R6、R7）**：启动与导出。判定：命令 `python app.py` —— 期望打印内网地址且浏览器可访问；命令 `python export.py` —— 期望生成 `out.csv`，首行等于 `序号,姓名,手机号,随行人数,提交时间`。

## 8. 验证方式

python app.py        # 期望：打印 Listening on http://<内网IP>:8000

- 任一条不通过：回到「执行步骤」第 3 步修，不要继续往下。
- 需要用户配合：用手机连同一 WiFi 打开内网地址实测一次（A1 与 A4）。

## 9. 执行步骤

1. 建工程、依赖与数据表（R6）→ 产物：`signup.db` 建表脚本可重复执行。
2. 报名页与提交接口（R1/R2/R3）→ 产物：本机浏览器可提交并落库。
3. 名单页（R4）→ 产物：`/list` 可读，手机号打码。
4. 导出脚本（R6）→ 产物：`out.csv` 生成。
5. 压测与调优（R5）→ 产物：`ab` 压测报告贴在 README。
6. 写 README 与启动说明（R7）→ 产物：交给班长即可运行。

- 可中断点：第 3 步做完先让班长用手机看一次名单页。
- 顺序依赖：第 4 步依赖第 1 步的表结构；第 5 步必须在第 2、3 步之后。
- 每步做完先跑第 8 段对应命令。

## 11. 何时必须停下来问人

- 触发条件：需要把服务暴露到公网 → 停下来（触碰第 5 段非目标），先问用途再决定。
- 触发条件：需要收集姓名、手机号、随行人数以外的个人信息 → 停下来问，涉及隐私与合规。
- 触发条件：42 并发下 P95 超过 500 ms 且要换技术栈（如换 ASGI 框架）→ 停下来给两种取舍让用户选。
