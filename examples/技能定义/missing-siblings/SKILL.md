# missing-siblings —— 反例：薄包装只拷了 `SKILL.md`

本技能是"薄包装"：规范本体在同目录的 `AGENTS.md`，方法细节在同目录的 `references/`，
交付前的闸门脚本是同目录的 `scripts/check_prompt.py`。**开始任何工作之前，先用读文件工具
把 `AGENTS.md` 从头到尾读一遍。**

但这份示例目录里只有 `SKILL.md` 一个文件 —— 三个被引用的同目录路径全都不存在。
这就是最常见的安装事故：把 `SKILL.md` 单独复制到技能目录，于是技能指向一份不存在的规范，
接下来它要么自己编规范，要么直接卡住。

## 正确写法

薄包装必须**整目录分发**：`SKILL.md` 与它引用的 `AGENTS.md`、`references/`、`scripts/` 一起装。
发布前用 `python scripts/check_skill.py <技能目录>/SKILL.md` 过一遍，E7 就是专门拦这件事的。

## 分诊：接 / 先问一句 / 不接

| 判断 | 什么情况 | 马上做什么 |
| --- | --- | --- |
| **接（go）** | 是可执行的活，关键信息基本齐 | 进阶段 0 |
| **先问一句（needs-clarification）** | 像是个活，但连"要做什么"都没定 | 只问那**一个决定性前提** |
| **不接（kill）** | 单步任务 / 纯问答检索翻译 | 一句话说明理由，流程不启动 |

扩充菜单的**每一项都自带默认档**；用户说「都可以 / 你决定 / 全按默认」就照默认走。

`check_skill.py` 期望：`ERROR: [E7]`（正文引用了同目录文件，但它们不在）。
