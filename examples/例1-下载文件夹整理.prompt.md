# 任务：把 D:\Downloads 自动整理成分类目录（Windows + Python，零依赖）

## 1. 角色与目标

你是一名 Windows 桌面自动化工程师。目标：写一个零依赖的 Python 脚本，把 `D:\Downloads` 里的
散落文件按扩展名归到分类子目录，并提供双击即可运行的入口。

做完算成功的定义：用户在真实目录上双击 `run.cmd`，60 秒内完成一次整理，屏幕上打印出「源路径 → 目标路径」
的记录表，且整理前后文件总数不变（一个都没丢）。

## 2. 背景与已知事实

- [用户原话] 「下载文件夹乱得没法看，先按类型分开就行，千万别删东西。」
- [用户原话] 电脑是 Windows 11，已装 Python 3.12；不想装任何额外的库。
- [仓库实测] `D:\Downloads` 当前 1284 个文件、合计约 23 GB；其中 `.zip` 412 个、`.jpg/.png` 538 个、`.pdf` 96 个，其余混合。
- [外部资料 https://docs.python.org/3.12/library/shutil.html] `shutil.move` 在同盘是重命名、跨盘会退化为复制+删除，跨盘耗时明显更长。
- [AI 推断] 用户希望每天自动跑（未确认，见第 10 段）。

## 3. 交付物

| 路径 | 是什么 | 格式 / 规模 |
| --- | --- | --- |
| `D:\tools\download-tidy\tidy.py` | 整理脚本本体 | 单文件，≤200 行，仅标准库 |
| `D:\tools\download-tidy\run.cmd` | 双击入口 | ≤5 行，调用 py -3 |
| `D:\tools\download-tidy\README.md` | 用法与配置说明 | ≤60 行，含扩展名表怎么改 |
| `D:\tools\download-tidy\tidy.log` | 运行日志（追加写） | 每行含时间戳与动作 |

## 4. 需求（R#）

- **R1** 按扩展名把文件移动到 `D:\Downloads\_分类\` 下的四个子目录：图片（jpg jpeg png gif webp）、文档（pdf docx xlsx pptx txt md）、压缩包（zip rar 7z）、其他。
- **R2** 目标目录已有同名文件时，新文件改名为 `<原名>-1.<扩展名>`，再冲突则 `-2`，最多递增到 `-99`；到 `-99` 仍冲突就跳过并记日志。
- **R3** 以下三类一律不动：目录本身、隐藏或系统属性文件、以及以 `.part` `.crdownload` `.tmp` 结尾的文件。
- **R4** 单个文件移动失败时，把「源路径 + 错误原因」写入 `tidy.log` 后继续处理其余文件；全部处理完的退出码为 0，只有「一个文件都没处理成功」时才返回 1。
- **R5** 支持 `--dry-run`：只打印将要执行的移动清单，磁盘上不发生任何改动。
- **R6** 在 1284 个文件（约 23 GB、同盘移动）的真实目录上，单次运行 ≤ 60 秒；跨盘移动不受此限。
- **R7** 重复运行是幂等的：已经在 `_分类` 下的文件不再被移动，第二次运行打印的移动条数为 0。

## 5. 非目标

- 不做内容识别：不按图片内容、文档主题或文件时间分类。
- 不删除任何文件，不清空回收站，不做去重删除。
- 不做图形界面、不做系统托盘、不做后台常驻。
- 不引入第三方依赖（不装 pandas，不用 pywin32，不调 PowerShell 做移动）。
- 不改动 `D:\Downloads` 之外的任何目录。

## 6. 技术约束

- Python 3.12，仅标准库：`pathlib` / `shutil` / `argparse` / `logging` / `os`。
- Windows 11 环境，路径一律用 `pathlib.Path` 拼接，禁止硬编码反斜杠字符串。
- 扩展名映射表与根目录放在文件顶部常量区，用户改一行即可调整分类。
- 控制台输出中文；日志文件以 UTF-8 编码追加写入。
- 禁止出现 `shutil.rmtree` / `os.remove` / `os.unlink`。

## 7. 验收标准（A#）

- **A1（对应 R1、R7）**：给定 `D:\Downloads` 含 `a.jpg` 与 `b.zip`，运行后二者分别位于 `_分类\图片\` 与 `_分类\压缩包\`；再运行一次，位置不变。判定：命令 `python tidy.py && python tidy.py` —— 期望第二次运行的移动条数为 0。
- **A2（对应 R2）**：给定目标目录已有 `a.jpg`，当放入新的同名文件并运行，则出现 `a-1.jpg` 且 `a.jpg` 仍在。判定：命令 `python tidy.py` 后检查 `_分类\图片\`，期望同时存在 `a.jpg` 与 `a-1.jpg` 两个文件。
- **A3（对应 R3）**：给定根目录存在 `demo.part` 与隐藏文件 `hidden.txt`，运行后两者仍在原位。判定：命令 `python tidy.py` —— 期望日志出现「跳过 demo.part」与「跳过 hidden.txt」两行。
- **A4（对应 R5）**：`--dry-run` 前后文件总数不变。判定：阈值 文件数差值 = 0（测量方法：运行前后各执行一次 `(Get-ChildItem D:\Downloads -Recurse -File).Count` 比对）。
- **A5（对应 R6）**：在真实目录上计时。判定：阈值 单次运行 ≤ 60 秒（测量方法：`Measure-Command { python tidy.py }`，连测 3 次取中位数）。
- **A6（对应 R4）**：人为把某个文件设为只读后运行，脚本不中断。判定：人工 用户 检查 `tidy.log` 中该文件有一条错误记录，且进程退出码为 0，即为通过。

## 8. 验证方式

```powershell
cd D:\tools\download-tidy
python tidy.py --dry-run     # 期望：打印移动清单，磁盘无改动
python tidy.py               # 期望：退出码 0，tidy.log 追加记录
python tidy.py               # 期望：第二次运行移动条数为 0（幂等）
```

- 任一条不符合：回到「执行步骤」第 2 步修，不要继续往下。
- 需要用户配合：在真实 `D:\Downloads` 上跑之前，先执行 `dir /s /b > before.txt` 留一份清单，
  跑完用同一命令生成 `after.txt` 做数量比对。

## 9. 执行步骤

1. 建目录、常量区与日志骨架（R1/R3 的扩展名表与排除规则）→ 产物：`tidy.py` 可运行并打印参数帮助。
2. 实现扫描、分类与移动（R1/R2）与 `--dry-run` 预演（R5）→ 产物：`python tidy.py --dry-run` 在真实目录上打印正确清单。
3. 加跳过规则、失败兜底与日志（R3/R4）→ 产物：`tidy.log` 有对应记录。
4. 加幂等判断（R7）→ 产物：连跑两次，第二次移动条数为 0。
5. 写 `run.cmd` 与 `README.md`（R6 的耗时说明）→ 产物：双击即可运行。

- 可中断点：第 2 步做完先把 dry-run 清单给用户看。
- 顺序依赖：第 3 步必须在第 2 步之后，跳过规则要基于真实扫描结果编写。
- 每步做完立刻跑第 8 段对应命令，不要攒到最后一起验。
